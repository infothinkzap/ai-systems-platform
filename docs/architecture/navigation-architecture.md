# Navigation Architecture

The navigation must balance the structural hierarchy with the semantic journey. It should be clean, restrained, and systems-oriented.

## Primary Global Navigation

- **Think**: Dropdown or landing page leading to core philosophies and insights.
- **Capabilities**: The underlying intelligence primitives.
- **Systems**: The reusable products (Product Mode).
- **Services**: Custom consulting and engineering (Systems Mode).
- **Case Studies**: Evidence and deployed work.
- **About**: The founders and brand boundaries.

## Secondary / Utility Navigation
- **Start Discovery** (Primary CTA button, persistent)

## Footer Navigation
- **Company**: About, Contact, Work With Us
- **Domains**: Business Intelligence, Knowledge Intelligence, Personal Intelligence
- **Legal**: Privacy, Terms

## The Semantic Cross-Navigation (In-Page)
Structural navigation is just the frame. The true navigation happens *within* the pages via semantic linking (powered by the graph):

- On a **Persona** block (e.g., CFO): Link to `Financial Complexity` (Problem).
- On a **Problem** block: Link to `AI CFO` (System) and `Opportunity Discovery` (Service).
- On a **System** page: Link to `Document Intelligence` (Capability) and `Hours Saved` (Metric/Evidence).
- On a **Capability** page: Link to `Invoices` (Data Primitive) and `CA Automation` (System).

This ensures the user naturally traverses: Person → Problem → Capability → System → Outcome.
