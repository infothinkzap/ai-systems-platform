# Case Study Schema

Defines the structure for proof-of-work pages.

## 1. Frontmatter (MDX)
```yaml
id: "casestudy:invoice_automation_beta"
title: "Zero-Touch Invoice Reconciliation"
client_type: "Mid-Market Accounting Firm"
```

## 2. Dynamic Graph Injection
- **Validates System**: `DEMONSTRATES` → `product:ca_automation`
- **Evidence Type**: e.g., `prototype_evidence` or `production_observation`

## 3. Editorial Body (Human Written)
Must strictly adhere to the rigorous question structure:

- **WHAT WAS THE PROBLEM?**: The business friction.
- **WHO EXPERIENCED IT?**: The persona.
- **WHAT WAS THE EXISTING WORKFLOW?**: The manual process.
- **WHERE WAS THE FRICTION?**: The bottleneck (e.g., data entry).
- **WHAT DID WE DISCOVER?**: The insight during analysis.
- **WHAT SYSTEM DID WE DESIGN?**: The architecture.
- **WHY DID WE DESIGN IT THAT WAY?**: The engineering rationale.
- **WHAT WAS AI'S ROLE?**: The probabilistic extraction.
- **WHAT WAS SOFTWARE'S ROLE?**: The deterministic routing and API sync.
- **WHAT WAS HUMAN JUDGMENT'S ROLE?**: The exception handling.
- **WHAT WAS THE OUTCOME?**: Quantitative/Qualitative results.
- **WHAT REMAINS UNKNOWN?**: Radical honesty about edge cases or future V2 goals.
