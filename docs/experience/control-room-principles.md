# Control Room Principles

## 1. Laboratory, Not Dashboard
The Control Room at `/explore` is an architectural instrument for system design. It is not a business intelligence dashboard. It should feel analytical, deliberate, and structural.

## 2. Default to Reality
When loading the Control Room, always default to an honest, deployed system (e.g., Manaswini Designer Studio). Demonstrate the methodology on real operational architecture first before inviting users to explore conceptual prototypes.

## 3. Visually Meaningful Deconstruction
Interactions like "Remove AI" must not just toggle a boolean. They should visually deconstruct the system to reveal the underlying deterministic and human architecture, proving that the system can still function (or showing exactly where it degrades) without intelligence.

## 4. Traceable Decisions
Every AI capability or decision node must be structurally traceable back to its enriched data, raw data, and ultimate source. This trace should be experiential (animated pathways) to build trust in the methodology.

## 5. Spectrum of Responsibility
Allocating responsibility is the core interaction. Nodes must support explicit states: HUMAN, DETERMINISTIC, AI, HYBRID, and NO AI REQUIRED. The UI must ensure users understand AI is an architectural choice, not a default requirement.
