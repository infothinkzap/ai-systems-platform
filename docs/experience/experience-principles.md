# Terrawave Experience Principles

## 1. System First, AI Second
AI is not the starting point. The system is. The website must demonstrate how Terrawave thinks by visually grounding every AI interaction in the underlying business problem, workflow, and data.

## 2. Epistemic Honesty
Systems must declare their true status. Do not collapse maturity (e.g. deployed, building, concept), offering mode (applied, reusable, exploratory), and epistemic status (validated, tested, designed, hypothesis). If a system is theoretical, the UI must visually state that it is a hypothesis or concept. If it is deployed, it should state its operational reality.

## 3. Automation Does Not Eliminate Accountability
Automation relocates accountability deliberately. Visual experiences (like the Intelligence Control Room) should emphasize the preservation of human judgment and deterministic validation, even when AI is introduced.

## 4. Architectural Restraint
The website is a structural instrument, not a generic SaaS landing page.
- Do NOT use: Neon gradients, 3D WebGL, glassmorphism, decorative excessive animation, generic product cards.
- DO use: Structural lines, graph nodes, restrained transitions, progressive disclosure, and the canonical light-first palette (#F4F2EC, #17191B, #3FAF9B).

## 5. Explicitly Support "No AI Required"
A valid and celebrated outcome of Terrawave's methodology is concluding that AI is unnecessary. This must be a prominent, selectable, and visually respected state across interactive components.
