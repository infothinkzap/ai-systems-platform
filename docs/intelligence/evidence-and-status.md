# Maturity & Evidence Framework

Terrawave requires strict adherence to reality. We do not invent evidence, customers, revenue, performance statistics, or results. 

Every entity in the ontology (especially Products, Systems, and Claims) must be defined using a tripartite framework: **System Maturity**, **Epistemic Status**, and **Evidence**. Do not conflate these fields.

## 1. System Maturity
*Answers: "What exists in engineering reality?"*

- **concept**: An idea or architectural pattern that has been defined but not yet engineered.
- **research**: Active exploration, literature review, or feasibility testing.
- **prototype**: A functional, proof-of-concept build that demonstrates core capabilities but is not production-ready.
- **building**: Active, heavy engineering and development phase for a V1 product.
- **in-development**: Iterative development on an existing codebase.
- **deployed**: Running in a live environment, being used by real users or processing real data.
- **commercial**: A fully mature, monetized offering available to the broader market.

## 2. Epistemic Status
*Answers: "How confident are we in this claim or system's value?"*

- **hypothesis**: We believe this to be true or valuable, but lack rigorous data.
- **observed**: We have seen this problem/solution pattern in the wild.
- **designed**: We have structurally mapped how to solve it.
- **tested**: We have run controlled tests.
- **validated**: We have confirmed that the system achieves the desired outcome in the real world.
- **established**: This is a known, undeniable truth within our operational model (e.g. Core Philosophies).

## 3. Evidence Types
*Answers: "What backs up the epistemic status?"*

Evidence must be modeled separately as an explicit array of tags or objects. Do not invent evidence.
Possible evidence types:
- **internal_reasoning**: Derived from first-principles thinking.
- **prototype_evidence**: Derived from internal sandbox testing.
- **experiment**: Derived from controlled, structured trials.
- **production_observation**: Derived from monitoring live systems.
- **customer_evidence**: Derived from direct client feedback or case studies.
- **quantitative_measurement**: Hard data derived from metrics (e.g., logs proving hours saved).
